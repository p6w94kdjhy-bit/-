# 종목② 실물 테스트 — 순서 · 오류 알리는 법 · 시간 줄이는 순서

코드 브랜치: `claude/jellibi-agv2-course2-yha1tn` (GitHub Desktop → Fetch → Current Branch 에서 이 브랜치 선택 → Pull)
종목①만 돌릴 때는 `claude/jellibi-agv2-course1-rnqx70` (예전 이름 `claude/jellibi-agv2-contest-rnqx70` 과 같은 코드).

## 1. 오류가 났을 때 알리는 법

로봇이 주행 중 일어난 일을 스스로 저장한다(주행 기록). 케이블 없이 달려도 된다.

1. 로봇이 멈추거나 이상하게 움직이면 **버튼을 눌러 정지**시킨다 (전원을 바로 끄지 말 것 — 버튼을 눌러야 마지막 기록까지 저장됨).
2. USB 케이블을 꽂고 Arduino IDE 시리얼 모니터(115200)를 연다. 로봇이 다시 시작하면서 아래 블록을 출력한다.
   ```
   ===== 지난 주행 기록 (이 줄부터 '기록 끝'까지 복사해서 전달) =====
     0.00 START
     0.29 NODE H4 N err=23
     ...
   ===== 기록 끝 =====
   ```
3. 그 블록과 `----- config.h (로봇 안의 값) -----` 블록을 **그대로 복사**해서 붙여 넣는다.
4. 아래 세 줄을 함께 적는다.
   - 어디서: 예) "E4 에서 D4 로 가다가"
   - 증상: 예) "선을 벗어남 / 멈춤 / 반대로 돎 / 팔레트 떨어짐 / 장애물을 밂"
   - 몇 번 중 몇 번: 예) "3번 중 2번"

출발 전에는 기록이 지워지지 않는다. 다시 출발(버튼·태그)하는 순간부터 새 기록으로 덮어쓴다.
컴파일·업로드 오류는 IDE 아래쪽 주황색 글자 전체를 복사해서 보낸다.

### 기록 읽는 법
| 줄 | 뜻 |
|---|---|
| `NODE E4 N err=23` | 북쪽(N)으로 달리며 E4 를 셈. 그 칸에서 가장 크게 치우친 정도 23% (60 이상이 자주 나오면 흔들림) |
| `STOP E4` | E4 위에 정지 완료 |
| `TURN L/R/U/E` | 좌회전 / 우회전 / U턴 / 칸 중간 U턴(장애물 앞·하역 후) |
| `TMISS` | 회전 중 선을 못 찾아 시간으로 멈춤 → 회전 보정 필요 |
| `OBST D4` | D4 쪽에 장애물 감지 |
| `LANE ? O X` | 후보 통로 D2 D4 D6 상태 (? 모름, O 열림, X 막힘) |
| `PLAN A2 n=9` | A2 까지 경로 계산 (9칸) |
| `PICK` `DROP` `HOLD` `DONE` | 들기 / 내리기 / 2초 정차 / 완주 |
| `FATAL n` | 오류 정지 (아래 표) |
| `ABORT` | 버튼 비상정지 |

| FATAL | 뜻 | 먼저 볼 것 |
|---|---|---|
| 0 | config.h 값 미입력 등 | 시리얼의 `[FATAL]` 문장 |
| 1 | 4초 안에 다음 교차점을 못 찾음 (선 이탈·교차점 놓침) | 직전 `NODE` 줄의 err, 그 위치의 선 상태 |
| 2 | 경로가 직선이 아님 (코드 오류) | 기록 전체를 전달 |
| 10~12 | 맵 정의 오류 / 확인할 통로 없음 | `BLUE[]`, `CAND[]` |
| 20~22 | 팔레트 / 배송지 / 복귀 지점까지 길이 없음 | `LANE` 줄 (통로를 잘못 막힘 처리했는지) |

## 3. 시간 줄이는 순서

**조향 값은 처음부터 목표 속도로 찾는다** (코스 전체를 최고 속도로 달리는 것은 아님):
`tune_drive` 에서 `c`(새 조향) → `v` 를 눌러 속도를 올려 가며 `F` 를 달린다. 칸마다 출력되는 `err=` 가 40 이하이고
선을 벗어나지 않는 가장 빠른 속도 = 그 조향 값으로 쓸 수 있는 최고 속도.
넘으면 업로드 없이 `K`/`k`(게인 ±5), `T`/`t`(미분 ±15) 로 바꾸고 다시 `F`. 좌우로 흔들리면 `T`, 선 밖으로 밀려나면 `K`.
값이 정해지면 출력된 `#define C2_LT_KP …` `#define C2_LT_TD_MS …` 두 줄을 config.h 에 옮겨 적는다 (전원을 끄면 원래 값으로 돌아감).
여기서 정한 속도가 아래 3번 `SPEED_CRUISE` 의 상한이다.

그다음 코스 전체는 **3회 연속 완주**한 상태를 기준으로 저장한다(그 값을 알려주면 커밋해 둠). 그다음 아래 순서로 **한 번에 하나만** 바꾸고, 바꿀 때마다 2~3회 달려 `DONE` 시각과 성공 횟수를 기록한다. 실패가 나오면 바로 앞 단계 값으로 되돌린다.

| 순서 | 바꿀 값 | 단계 | 효과가 큰 이유 |
|---|---|---|---|
| 1 | `LATE_BRAKE_PCT` | 0 → 40 → 55 → 70 | 정차하는 칸(회전·들기·내리기마다 1칸, 약 25회)을 처음부터 느리게 가지 않음. 가장 큼 |
| 2 | `SPEED_CARRY` | 98 → 120 → 140 | 팔레트를 든 구간이 20칸 이상. 팔레트가 흔들리거나 밀리면 되돌림 |
| 3 | `SPEED_CRUISE` | 168 → 190 → 210 | 빈 차 통과 구간. `NODE` 줄 err 가 커지면 멈춤 |
| 4 | `SPEED_ZONE` | 60 → 75 | 장애물 확인 칸(3~6칸). 장애물을 밀면 실격이므로 맨 마지막에, 조금만 |

- 보고 형식: `LATE_BRAKE_PCT 40 → 3회 중 3회 완주, DONE 71.2 / 70.8 / 71.5` + 마지막 주행 기록
- 배점: 시간 5점, 배송 2건 50점, 안정성 10점. 완주가 흔들리는 속도는 쓰지 않는다.
- 배터리 전압이 낮아지면 느려진다. 시간 비교는 충전 상태가 비슷할 때만 한다.

## 4. 이번에 추가된 것 (11-11)

| 기능 | 내용 | 끄는 법 |
|---|---|---|
| 부드러운 PD 조향 | 5ms 마다 조향, 선이 다가오는 속도까지 반영해 좌우 흔들림을 줄임. 종목②만 사용 | `C2_LT_SMOOTH 0` |

물리 시뮬레이션의 로봇 치수·모터 반응은 추정값이라 **실물 주행으로는 아직 확인되지 않았다.**
